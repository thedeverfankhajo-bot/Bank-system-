# BankSystem — سیستم بانک برای بدراک

پلاگین مستقل بانک و کیف پول برای سرورهای Minecraft Bedrock که از PocketMine-MP API 5 استفاده می‌کنند.

## امکانات

- کیف پول جدا از موجودی حساب بانکی
- پنل بومی Bedrock با داشبورد رنگی، دکمهٔ تازه‌سازی موجودی و پیش‌نمایش سه تراکنش اخیر، تاریخچهٔ صفحه‌بندی‌شده، رتبه‌بندی، انتقال و ابزارهای مدیریتی مجوزمحور
- تأیید نهایی در پنل پیش از انتقال به بازیکن یا تغییر مدیریتی موجودی
- واریز و برداشت برای بازیکن آنلاین و انتقال پول به حساب بازیکن آنلاین یا آفلاین؛ اگر بازیکن در داده‌های PocketMine دارای `LastKnownXUID` معتبر باشد، حساب آفلاین نیز می‌تواند بدون ورود مجدد او ایجاد و هنگام ورود به UUID واقعی پیوند بخورد
- رتبه‌بندی موجودی بانک و مشاهده سابقه تراکنش‌ها
- دستورات مدیریتی با مجوز مخصوص اپراتور
- ذخیره دائمی در SQLite و ثبت سوابق تراکنش
- ایجاد و نگهداری فایل‌های SQLite و WAL/SHM با دسترسی فقط مالک در POSIX، ساخت امن فایل و ردکردن مسیرهای symbolic link؛ ویندوز به ACL متکی است
- پشتیبانی اختیاری از رمزنگاری در حالت سکون با SQLCipher، فقط در صورتی که افزونهٔ PHP SQLite3 سرور با SQLCipher ساخته شده باشد؛ در صورت درخواست رمزنگاری و نبود قابلیت، پلاگین به حالت بدون رمزنگاری سقوط نمی‌کند
- API عمومی برای اتصال پلاگین‌های دیگر و رویداد BankTransactionEvent
- محاسبه پول با عدد صحیح در واحد خرد برای جلوگیری از خطای اعشاری
- تست‌های خودکار و CI در GitHub Actions با ماتریس PHP 8.1 تا 8.4

## نیازمندی‌ها و نصب

- PocketMine-MP API 5.0.0 یا جدیدتر از شاخه 5.x
- PHP 8.1+ و افزونه sqlite3

با دستور `/bank` یا `/bank panel` پنل بومی داخل بازی باز می‌شود. این پنل از فرم‌های داخلی PocketMine-MP استفاده می‌کند؛ بدون FormAPI کار می‌کند و نصب بودن FormAPI نیز مانع استفاده از پنل نمی‌شود.

برای ساخت فایل مستقل PHAR با PHP خط فرمان اجرا کنید: `php -d phar.readonly=0 tools/build-phar.php`. خروجی پیش‌فرض `build/BankSystem.phar` است؛ آن را در پوشه `plugins/` سرور قرار دهید. برای توسعه همچنان می‌توانید از DevTools استفاده کنید. پس از اولین اجرا، تنظیمات در `plugin_data/BankSystem/config.yml` و پایگاه داده در `plugin_data/BankSystem/bank.sqlite3` ایجاد می‌شوند.

### رمزنگاری اختیاری پایگاه داده

به‌صورت پیش‌فرض، فایل SQLite **رمزنگاری نمی‌شود** و امنیت آن به مجوزهای فایل و امنیت میزبان وابسته است. برای رمزنگاری در حالت سکون باید runtimeِ PHP دارای افزونهٔ `sqlite3` ساخته‌شده با SQLCipher باشد. در `plugin_data/BankSystem/config.yml` مقدار `storage.encryption-at-rest: true` را تنظیم و متغیر محیطی `BANKSYSTEM_SQLCIPHER_KEY` را در محیط اجرای سرور PocketMine فراهم کنید. کلید یا عبارت‌عبور تصادفی حداقل ۳۲ بایتی انتخاب کنید؛ آن را داخل config، مخزن Git یا گزارش خطا قرار ندهید. اگر SQLCipher یا کلید در دسترس نباشد، افزونه هنگام شروع غیرفعال می‌شود و داده را به‌صورت متن ساده باز نمی‌کند.

بسته‌های استاندارد PHP مخصوص PocketMine لزوماً SQLCipher ندارند؛ پیش از فعال‌سازی، runtime دقیق سرور را بررسی کنید. این گزینه را روی فایل قدیمی و رمزنگاری‌نشدهٔ `bank.sqlite3` فعال نکنید. از سرور متوقف‌شده نسخهٔ پشتیبان بگیرید، پایگاه داده را با ابزار SQLCipher به‌صورت آفلاین مهاجرت دهید و نسخهٔ رمزنگاری‌شده را بررسی کنید. گم‌شدن کلید یعنی دسترسی به پایگاه دادهٔ رمزنگاری‌شده از دست می‌رود. نسخه‌های پشتیبان نیز باید به‌طور جداگانه محافظت شوند.

### سخت‌سازی مجوزها در ویندوز

در ویندوز، بیت‌های مجوز POSIX و `umask` کنترل دسترسی ایجاد نمی‌کنند. اسکریپت `tools/harden-windows-acl.ps1` برای پوشهٔ دادهٔ پلاگین و مسیرهای نسخهٔ پشتیبان، ACL را بازنشانی می‌کند و فقط به حساب سرویس PocketMine، حساب SYSTEM و مدیران محلی اجازهٔ دسترسی می‌دهد. PowerShell را با دسترسی مدیریتی اجرا کن و حساب سرویس واقعی را دقیق بده:

```powershell
# ابتدا مسیرها را مرور کن
.\tools\harden-windows-acl.ps1 -DataDirectory 'C:\PocketMine\plugin_data\BankSystem' -ServerAccount 'NT AUTHORITY\LOCAL SERVICE' -BackupDirectory 'D:\PocketMineBackups\BankSystem' -WhatIf

# سپس ACL را اعمال و بررسی کن
.\tools\harden-windows-acl.ps1 -DataDirectory 'C:\PocketMine\plugin_data\BankSystem' -ServerAccount 'NT AUTHORITY\LOCAL SERVICE' -BackupDirectory 'D:\PocketMineBackups\BankSystem'
icacls 'C:\PocketMine\plugin_data\BankSystem' /verify /T
```

مسیرها باید از قبل وجود داشته باشند. مقدار `ServerAccount` را با هویت واقعی سرویس جایگزین کن؛ حدس اشتباه ممکن است نوشتن بانک یا پشتیبان‌گیری را مختل کند. اسکریپت ACLهای داخل مسیرهای هدف را بازنشانی می‌کند، پس آن‌ها را با دقت انتخاب کن و همهٔ مسیرهای نسخهٔ پشتیبان را نیز وارد کن. بعد از اجرا، دسترسی واقعی سرویس به پایگاه داده و پشتیبان‌ها را آزمایش کن.

## دستورات

| دستور | کاربرد |
|---|---|
| /bank یا /bank panel | بازکردن پنل تعاملی بانک داخل بازی |
| /bank balance | نمایش کیف پول، حساب بانک و مجموع |
| /bank deposit <مبلغ> | واریز از کیف پول به بانک |
| /bank withdraw <مبلغ> | برداشت از بانک به کیف پول |
| /bank pay <بازیکن> <مبلغ> | انتقال پول کیف پول به بازیکن آنلاین یا حساب ثبت‌شدهٔ آفلاین |
| /bank top | ۱۰ حساب با بیشترین موجودی بانک |
| /bank history [صفحه] | مشاهده سوابق تراکنش |
| /bank admin give <بازیکن> <wallet/bank> <مبلغ> | افزودن موجودی به حساب آنلاین یا آفلاین ثبت‌شده |
| /bank admin take <بازیکن> <wallet/bank> <مبلغ> | کم‌کردن موجودی حساب آنلاین یا آفلاین ثبت‌شده |
| /bank admin set <بازیکن> <wallet/bank> <مبلغ> | تنظیم موجودی حساب آنلاین یا آفلاین ثبت‌شده؛ صفر مجاز است |

مجوز banksystem.admin به‌صورت پیش‌فرض برای اپراتورها فعال است. مبالغ باید حداکثر دو رقم اعشار داشته باشند. در حالت عادی مبلغ باید مثبت باشد. سقف تراکنش، اختلاف موجودی قبل و بعد از دستور مدیریتی set را نیز محدود می‌کند؛ یعنی سقف روی میزان تغییر اعمال می‌شود نه روی موجودی نهایی. وضعیت محدودیت زمانی تراکنش هر بازیکن هنگام خروج او از سرور پاک می‌شود. برای کار با بازیکن آفلاین، BankSystem ابتدا حساب موجود را بررسی می‌کند و در صورت نبودن آن، فقط با XUID عددی ذخیره‌شده در داده‌های خود PocketMine حساب آفلاین می‌سازد؛ نام به‌تنهایی برای ساخت شناسه کافی نیست. هنگام ورود بعدی، حساب موقت و ارجاع‌های تاریخچه به UUID واقعی منتقل می‌شوند. اگر XUID ذخیره‌شده موجود نباشد، نام مبهم باشد یا دو هویت با هم تعارض داشته باشند، عملیات رد می‌شود تا پول به حساب اشتباه منتقل نشود.

## تنظیمات

فایل resources/config.yml شامل نماد پول، موجودی اولیه، سقف تراکنش و زمان انتظار میان تراکنش‌هاست. گزینهٔ `storage.encryption-at-rest` به‌صورت پیش‌فرض خاموش است و تنها برای runtime دارای SQLCipher قابل فعال‌سازی است. اعداد پولی در YAML به شکل متن نقل‌قول‌شده ذخیره شده‌اند تا هنگام خواندن تنظیمات گرد نشوند.

## API

سرویس با Main::getBankService() دریافت می‌شود. مبلغ‌ها در API به صورت واحد خرد عدد صحیح هستند؛ مثلاً 1250 برابر با 12.50 است. برای جلوگیری از ثبت حساب‌های تکراری، کلید حساب UUID بازیکن است نه نام قابل تغییر او. برای ثبت امن بازیکن آنلاین از `getAccountForPlayer($player)` یا `registerOnlinePlayer($player)` استفاده کنید؛ `getAccount($uuid, $name)` فقط حساب موجود را می‌خواند و از نام ورودی برای ساخت یا تغییر هویت حساب استفاده نمی‌کند. متد `findAccountByName()` حساب موجود را با نام آخرین‌بار دیده‌شده جست‌وجو می‌کند و اگر رکوردی نباشد از XUID معتبر ذخیره‌شده در PocketMine برای ساخت حساب آفلاین استفاده می‌کند؛ `findAccountByUuid()` جست‌وجوی فقط‌خواندنی دارد و `transferToNameAs($player, $playerName, $amountMinor)` انتقال به حساب آفلاین را پشتیبانی می‌کند و هویت مبدأ را از شیء واقعی بازیکن می‌گیرد. اگر XUID در داده‌های ذخیره‌شدهٔ PocketMine موجود نباشد، با رکورد قدیمی پیوند قابل‌اعتماد برقرار نشود یا نام مبهم باشد، عملیات امن رد می‌شود؛ در این حالت از API می‌توان با UUID معلوم حساب را صریح انتخاب کرد.

برای تراکنش بازیکن، از `depositAs($player, $amountMinor)`، `withdrawAs($player, $amountMinor)`، `transferAs($player, $targetUuid, $amountMinor)` یا `transferToNameAs($player, $targetName, $amountMinor)` استفاده کنید. این متدها فقط شیء واقعی و متصل PocketMine `Player` را می‌پذیرند، مجوز `banksystem.use` را بررسی می‌کنند و UUID/نام عامل را از خود بازیکن می‌خوانند. ثبت حساب ورود نیز از `registerOnlinePlayer($player)` انجام می‌شود. امضاهای قدیمی `deposit()`، `withdraw()`، `transfer()`، `transferToName()` و `registerOnlineAccount()` که هویت را از رشته‌های ورودی می‌گیرند برای کشف منبع حفظ شده‌اند اما با `BankException` بسته می‌شوند و تغییری در پول ایجاد نمی‌کنند.

برای عملیات مدیریتی API، از `giveAs($sender, $targetUuid, $targetName, $bucket, $amountMinor)`، `takeAs(...)` و `setBalanceAs(...)` استفاده کنید. هر متد، مجوز `banksystem.admin` را از شیء واقعی `CommandSender` دوباره بررسی می‌کند و هویت عامل را خودش ثبت می‌کند. امضاهای قدیمی `give()`، `take()` و `setBalance()` که UUID/نام عامل را از فراخواننده می‌گیرند برای سازگاری منبعی باقی مانده‌اند، اما اکنون `BankException` می‌اندازند و هیچ موجودی را تغییر نمی‌دهند؛ رشته‌های ورودی به‌تنهایی اثبات مجوز نیستند. جزئیات در `docs/API.md` آمده است.

هر تراکنش موفق همراه با رکورد حسابرسی داخل یک تراکنش SQLite ثبت می‌شود. روی سیستم‌های POSIX، پلاگین برای فایل پایگاه‌داده و فایل‌های جانبی موجود مجوز دسترسی فقط برای مالک (0600) اعمال می‌کند؛ در ویندوز باید ACLهای سیستم فایل مناسب باشند. پس از commit، رویداد BankTransactionEvent اجرا می‌شود؛ این رویداد پس از ثبت نهایی اجرا می‌شود و برای لغو تراکنش نیست.

## تحلیل امنیتی کد PHP

گردش‌کار `.github/workflows/php-security.yml`، قواعد امنیتی PHP در Semgrep را روی کدهای `src/` و `tests/` اجرا و گزارش SARIF را به GitHub Code Scanning می‌فرستد. این بررسی مکمل تست، lint و `composer audit` است و تضمین کشف تمام آسیب‌پذیری‌ها نیست؛ CodeQL موجود فقط گردش‌کارهای GitHub Actions را تحلیل می‌کند، نه PHP.

## ساخت و تست

```sh
composer install
composer test
composer lint
php -d phar.readonly=0 tools/build-phar.php
```

CI تست‌های واحد و SQLite را روی PHP 8.1 تا 8.4 اجرا می‌کند. گردش‌کار جداگانه، فایل رسمی سرور PocketMine-MP نسخه 5.44.3 و محیط رسمی و توصیه‌شدهٔ PHP 8.2 مخصوص PMMP را دانلود و با SHA-256 بررسی می‌کند، سپس PHAR افزونه را می‌سازد و شروع سرور و فعال‌شدن BankSystem را می‌سنجد. در صورت موفقیت، artifact با نام `BankSystem-API5-PHAR` شامل فایل `BankSystem.phar` و هش `BankSystem.phar.sha256` منتشر می‌شود. پس از استخراج artifact، صحت فایل افزونه را با دستور `sha256sum --check BankSystem.phar.sha256` بررسی کنید. همچنین artifact با نام `PocketMine-5.44.3-PHP82-Linux-x86_64` شامل PHAR رسمی سرور، آرشیو runtime رسمی PHP 8.2 و فایل SHA-256 آن‌ها منتشر می‌شود. هر دو artifact به مدت ۱۴ روز از صفحهٔ اجرای گردش‌کار قابل دریافت‌اند. آزمون راه‌اندازی و حساب آفلاین جای آزمایش دستی UI و تراکنش‌ها با کلاینت واقعی Bedrock روی سرور آزمایشی را نمی‌گیرد.
